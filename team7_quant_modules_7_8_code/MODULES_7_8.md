# 모듈 7·8 — 실행 및 인계 안내

모듈 7은 보호풋·선물 주문과 현금 회계를 처리하고, 모듈 8은 성과를 비교한다.
팀원 제공 코드 사본에 추가했다. GitHub에는 게시하지 않았다.
종목 선정·가중치·기초 주식 체결을 담당하는 모듈 1~6은 유지한다.
모멘텀은 기본 설정에서 독립 팩터이며 가치·퀄리티·모멘텀 중립 가중치는 0.4·0.4·0.2다.

## 바로 확인

프로젝트 폴더를 열고 실행한다. Python 3.11 이상을 사용한다.

```bash
python -m pip install -e .
python run_modules_7_8.py --check
python run_modules_7_8.py --baseline-only --out results/baseline_evaluation
```

`--check`는 미확정 거래비용과 최초 헤지일의 현금을 점검한다.
`--baseline-only`는 기존 무헤지 NAV만 평가하며, 헤지 결과로 표시하지 않는다.
이미 작성한 결과는 `results/baseline_evaluation/report.html`에서 볼 수 있다.
이번 배포의 준비된 입력을 읽는 데 API 키나 대용량 주가 원본은 필요하지 않다.

실제 헤지 비교는 필요한 입력을 채운 뒤 실행한다.

```bash
python run_modules_7_8.py
```

입력이 미완성이면 이유를 출력하고 종료코드 2로 끝난다. 비용이나 현금 비율을 임의로 채우지 않는다.

## 현재 필요한 두 가지

### 1. 팀원이 현금을 남긴 기초 운용 결과

현재 제공된 기초 파일은 첫 체결일(2016-01-04)의 현금이 0이다.
일부 거래불가 종목 때문에 일시적 잔액이 생기지만 기본 헤지 자금 배분은 반영되지 않았다.
모듈 5·6 담당자가 합의한 현금 배분을 반영해 다음 파일을 갱신해야 한다.

- `daily_nav.csv`: `date,strategy_id,nav,cash,cost,turnover`.
- `holdings.csv`: `date,strategy_id,stock_code,weight`. weight는 전체 NAV 대비 주식 비중이며 합계가 1보다 작아도 된다.
- `target_weights.csv`: 기존 열 유지. target_weight도 전체 NAV 대비 비중이며 잔여분은 현금이다.
- 가능하면 동일한 결과에 사용한 주가 캐시와 `monthly_regimes.csv`도 함께 제공한다.

헤지 현금은 기초 NAV의 cash에 이미 포함돼 있어야 한다.
기본적으로 이 현금을 한도로 사용한다. 따로 묶어둘 현금이 있다면
`templates/hedge_cash_limits.csv`의 date,strategy_id,hedge_cash_available을 채우고
`risk.cash_file`에 경로를 넣을 수 있다. 이 금액은 base_cash 이하이어야 한다.
현금 한도는 매일 새로 주입되는 자금이 아니다. 지불한 보험료·수수료와 선물 손익은 누적 관리한다.
앞 모듈이 이미 보험료로 사용한 돈을 다시 투자하면 현금 부족으로 중단한다.

기초 결과를 바꾼 다음에는 베타 특성도 다시 만든다.

```bash
python -m team7_quant build-risk-stock-cache --input STOCK_PRICES.xlsx --out data/cache/risk_stock_panel.npz
python -m team7_quant prepare-risk-data --input RAW_FOLDER --baseline results/backtest --stock-cache data/cache/risk_stock_panel.npz --margin-file data/risk_prepared/margin_rates.csv --out data/risk_prepared
```

RAW_FOLDER에는 제공했던 옵션·선물·지수·CD Excel과 `KOSPI200배당수익률.zip`을 둔다.
원본 주가가 표준 long CSV이면 date,stock_code,adj_close,volume(또는 trading_volume)을 사용한다.
기초 NAV·현금을 바꾼 뒤 기존 baseline_features를 재사용하면 입력 점검에서 검출한다.

### 2. 파생 거래비용 적용 기준

`config/base.json`의 네 비용은 null이다. 0%로 간주하지 않는다.
확정한 기준과 출처를 직접 입력하거나 비용 이력 파일을 지정한다.

| 설정 | 단위 |
|---|---|
| option_commission_rate | 옵션 프리미엄 약정금액에 대한 편도 수수료, 소수 비율 |
| future_commission_rate | 선물 약정금액에 대한 편도 수수료, 소수 비율 |
| option_slippage_ticks | 편도 슬리피지 호가 수. 프리미엄 10 미만 0.01pt, 이상 0.05pt로 환산 |
| future_slippage_points | 편도 슬리피지 포인트 |
| cost_source | 실제 수수료표 또는 팀에서 명시적으로 선택한 적용 기준 |

이력을 쓸 경우 `templates/derivative_costs.csv`를 채워 `risk.cost_file`에 넣는다.
필수 열은 effective_date, 위의 네 비용, source다. 적용일 이후에만 사용하고 과거로 소급하지 않는다.
세율·유관기관 비용 등의 포함 범위를 출처에 적어 이중 가산을 피한다.
현재 증권사 수수료가 과거 10년간 동일했다고 자동 가정하지 않는다.

## 회계와 체결

```text
헤지 후 NAV = 기초 NAV + 누적 파생 현금 증감 + 풋 평가액
총현금 = 기초 cash + 누적 파생 현금 증감
```

- 보험료는 현금에서 옵션 자산으로 이동한다. 매수대금을 당일 손실로 중복 차감하지 않는다.
- 선물 명목금액은 자산으로 더하지 않는다. 관측 종가 간 손익을 현금 증감에 반영한다.
- 증거금은 비용이 아니라 가용 현금의 제약이다. NAV에서 다시 빼지 않는다.
- 기초 주식의 원화 보유 경로를 유지하며 비례 매도·차입·외부 자금 추가는 하지 않는다.
- t일 종가로 목표를 정하고 다음 거래일 종가로 체결한다. 당일 가격은 체결 가능 수량과 비용에만 사용한다.
- 거래량이 0이거나 유효한 가격이 없으면 주문을 막고 기록한다. 만기에도 청산이 불가능하면 실제 결제 자료를 요구한다.
- 보유 현금·옵션 평가액·기초 주식 가치 및 일별 손익의 항등식을 매일 검사한다.

## 위험관리 규칙

- 풋: 수집한 월물별 95% 행사가 후보를 보유한다. 목표 수량은 베타 명목금액의 50%다.
- 만기 5거래일 전에 다음 월물로 교체한다. 수량은 월물 교체 또는 기초 리밸런싱 때 조정한다.
- 기본 NAV 낙폭 8·12·15%에서 순베타 상한을 0.8·0.5·0.2로 낮춘다.
- 6·10·13% 미만으로 5거래일 유지하면 한 단계씩 완화한다. 설정에 공개된 전략 규칙이다.
- 정수 계약·예산 부족·가격 변화 때문에 실제 베타가 한도를 넘은 일수도 기록한다. 손실 한도를 보장하는 규칙은 아니다.
- 60거래일 변동성과 252거래일 ES 95%는 헤지 후 NAV에서 계산한다. 준비 표본이 부족하면 빈칸이다.
- 지수 -10/-20/-30%, IV +10/+20%p의 마지막 보유 장부 스트레스 분석을 제공한다.
- 2017-03-27 승수 50만→25만원 변경 때 보유·계획 수량을 두 배로 조정한다.

## 증거금·배당 자료의 정확한 범위

`margin_rates.csv`는 정리한 게시 요율 이력이며 다른 월의 추정 시행일 표시를 유지한다.
55번 공지는 원본 PDF로 확인했다. 2020-03-18 시행, 3월 17일 정규장 종료 산출부터
위탁 11.10%, 유지 7.40%다. 2016~2025년 거래일 2,452개의 요율 결측은 없다.

사용 방식은 단독 선물 기초지수 명목금액×게시 요율에 의한 한도다.
선물·옵션 결합 포지션의 COMS 상계·가격 시나리오 전체를 복원한 증거금액은 아니다.
유지 요율 미달은 당일 기록하고 다음 거래일 종가의 감축 주문을 예약한다.
장중 추가증거금과 증권사의 실제 반대매매 시간을 재현한 것으로 해석하지 않는다.

배당은 KRX의 실제 일별 지수 배당수익률을 소수로 변환했다. 연간 배당의 임의 4개월 시차,
자료 전 q=0 대체는 제거했다. BSM 델타·스트레스의 q 입력으로 관측 배당수익률을 쓰지만,
이를 옵션 만기별 예상 배당률이라고 주장하지 않는다. 금리는 수집한 CD91의 연속복리 등가값이다.
선물 손익은 관측 종가 차이이며, 별도로 검증한 공식 정산가 현금 장부와 같다고 주장하지 않는다.

## 출력

- NO_HEDGE / PUT_ONLY / PUT_FUTURES의 같은 기초 장부 비교.
- `risk_daily_nav.csv`: NAV, 현금, 풋 평가액, 선물 손익, 증거금, 베타, 위험단계, ES·변동성.
- `risk_trades.csv`, `risk_events.csv`: 주문·체결과 제약·미달 사건.
- `performance_summary.csv`: CAGR·변동성·샤프·MDD·시장베타·CAPM alpha·정보비율.
- 연도별·국면별 성과와 관측 수, 원화 손익 분해, 스트레스, HTML 및 그래프.
- 샤프의 무위험 수익률은 전 거래일 CD 연율과 실제 달력 경과일로 계산한 대용 수익률이다.
- 비교 지수는 제공한 KOSPI200 가격지수다. 기초 NAV도 현금배당을 별도로 지급하지 않은 원본 경로다.
- 마지막 날은 평가액 기준이며 강제 청산 비용을 포함한 최종 회수액이 아니다.

## 남는 자료 한계 및 역할

상장폐지 전체 과거 주가가 없어 생존편향이 남는다. 샘플 두 기업으로 해결되지 않는다.
모듈 1 담당자가 당시 KOSPI 보통주 전체의 가격·시총·거래량·재무 공개일과 상폐·합병 회수처리를 보완하고,
모듈 9에서 시점 편향·생존편향의 남은 영향을 검토해야 한다.
이번 코드는 앞 모듈의 최신 수정 재무·거시 계열과 거래비용 규칙을 그대로 상속한다.
원래의 7년 워크포워드 결과를 사용하며 모듈 7·8에서 평가기간에 맞춰 파라미터를 재학습하지 않는다.
